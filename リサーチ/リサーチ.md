## 0. 最初に：この環境では文字起こしまで到達できなかった

依頼された手順は「yt-dlp で動画を集める → 文字起こし → 伸びている理由を抽象化」でしたが、
**この作業環境からは YouTube への通信が組織のネットワークポリシーで遮断されています。**

| 試したこと | 結果 |
| --- | --- |
| `yt-dlp` のインストール | 成功（v2026.07.04） |
| `yt-dlp` で YouTube 検索 | **失敗**：プロキシが `www.youtube.com:443` への接続に 403 を返す（ポリシー拒否） |
| WebFetch で YouTube ページ取得 | **失敗**：`EGRESS_BLOCKED` |
| WebFetch で解説記事サイト取得 | **失敗**：`EGRESS_BLOCKED`（外部ドメインが軒並み不可） |
| Web 検索 | **成功**（唯一通った経路） |

一時的なエラーではなくポリシーによる拒否のため、リトライや迂回はしていません。
そのため以下は **「再生数・登録者数・文字起こしを取得できていない」前提**で読んでください。
数字を推測で埋めることはしていません。

**したがってこのファイルは 2 部構成です。**

- **A パート**：この環境で実際に確認できた事実だけで書いた分析（タイトル・企画レベル）
- **B パート**：あなたの手元で流せば依頼どおりの結果が出るスクリプト（`collect.py`）と、
  文字起こしが取れた後に埋める表のテンプレ

### A-3. ここから抽象化できること（企画レベル）

1. **売れている軸は「技術解説」ではなく「経営シミュレーション」。**
   Claude Code の機能説明として作られた動画より、
   「会社」「社員」「部署」という**組織の比喩を丸ごと借りた**動画が並んでいる。
   視聴者が買っているのは機能ではなく **"一人でも組織を持てる"という体験** です。

2. **「実演」と「実験」が最頻出のフォーマット。**
   完成したノウハウを教える形ではなく、
   **やってみて、どこまでできて、どこが失敗したかを見せる**形が主流。
   これは失敗が減点にならないどころか、コンテンツの核になっているということ。

3. **数字が企画の骨格になっている。**
   「4体のエージェント」「6ステップ中4ステップ自動化」のように、
   **数えられる単位で構造化**されている。視聴前に完走イメージが立つ。

4. **入門と応用が別々に伸びている。**
   「完全入門」「知識ゼロで1週間」系と、「会社を回す」「サブエージェント完全版」系が併存。
   前者は母数、後者は濃さで伸びている、という別ルート。

> ⚠️ 1〜4 は**タイトルと検索スニペットから読み取れる範囲の推論**です。
> 「伸びている理由」を本当に確定させるには、下の B パートで文字起こしを取り、
> 冒頭 30 秒の構成・離脱ポイント・CTA の位置を実際に読む必要があります。

## B. 手元で依頼どおりに実行する手順

### B-1. 準備

```bash
pip install yt-dlp
cd リサーチ
```

### B-2. 実行

```bash
python3 collect.py
```

既定の絞り込み条件は依頼内容に合わせてあります。

| 条件 | 既定値 | 変更するオプション |
| --- | --- | --- |
| 投稿が直近半年以内 | 180 日 | `--days 90` |
| 登録者が少ない | 3 万人以下 | `--max-subs 10000` |
| 再生が伸びている | 1 万再生以上 | `--min-views 30000` |
| 登録者比で伸びている | 再生 ÷ 登録者 ≧ 1.0 | `--min-ratio 3.0` |
| 選ぶ本数 | 10 本 | `--top 10` |

**「登録者が少ないのに伸びている」の判定には `再生数 ÷ 登録者数` を使っています。**
この比率が高いほど、既存の登録者ではなく**アルゴリズムが外に配った**＝企画そのものが強い、と読めます。
まず `--min-ratio 1.0` で回して、候補が多すぎたら 3.0、5.0 と上げてください。

### B-3. 出てくるもの

```
リサーチ/out/
  candidates.json    全候補のメタデータ
  selected.json      条件を満たした上位10本
  selected.csv       Excel / スプレッドシートで開ける表
  subs/              取得した字幕（.srt）
  transcripts/       読める形に整形した文字起こし（.md）
```

`transcripts/*.md` が揃ったら、そのフォルダごと私に渡してください。
A-2 の表を**文字起こしベースで書き直します**（下のテンプレを埋める形になります）。

### B-4. 文字起こしが取れた後に埋める表（テンプレ）

```markdown
| # | タイトル | 再生 | 登録 | 比率 | 冒頭30秒のつかみ | 提示する成果物 | 失敗の開示 | 尺 | CTA |
|---|---------|-----|-----|-----|----------------|--------------|----------|---|-----|
| 1 |         |     |     |     |                |              |          |   |     |
```

観察する項目（伸びる理由はほぼこの 5 つに出ます）:

| 観察項目 | 何を見るか |
| --- | --- |
| **冒頭 30 秒** | 結論・完成物を先に見せているか／自己紹介から入っていないか |
| **画面の中身** | スライドか、実際のターミナル操作か（実操作のほうが強いはず） |
| **失敗の扱い** | うまくいかなかった箇所を残しているか、編集で消しているか |
| **再現可能性** | プロンプト全文・ディレクトリ構成を画面に出しているか |
| **視聴者の変換** | 「あなたもできる」と言う位置とタイミング |

## C. あなたのnoteへの応用（このリサーチの本来の目的）

A-2 の共通点は、そのまま**あなたのnote企画に移植できます**。

| 動画側の勝ち筋 | あなたのnoteへの翻訳 |
| --- | --- |
| 技術用語を職場の比喩に翻訳（サブエージェント→AI社員） | **ChatGPT → 「外部脳」「記憶の代わり」** ／ すでにあなたの企画に入っている強い比喩 |
| 「やってみた」＝実験の同伴 | 完成したノウハウではなく、**AI副業を始める過程をそのまま記録**する形 |
| 具体的な数字で骨格を作る | 「1日3回のリマインド」「朝10分で1日を確定させる」など**数えられる単位**に落とす |
| 出し惜しみしない宣言 | 無料部分に**一番痛い実体験を丸ごと1つ**置く |
| 対象者を明示 | 「記憶が抜ける人へ」と冒頭で名指しする |
| 失敗を隠さない | できなくなったこと・諦めた業務を書く。ここが最大の差別化になる |

特に **「技術を生活の比喩に翻訳する力」** は、
高次脳機能障害の当事者として "AI を外部脳として使う" と言えるあなたが、
このジャンルの誰よりも自然にできる部分です。
